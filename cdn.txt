chuẩn bị:
    - truy cập cloudinary lấy : cloudName , API key, API secret
    - cài npm install cloudinary multer multer-storage-cloudinary tại server

    - configuration file (vd : cloudinary.ts)
        + config bằng cloudName , API key, API secret
        -> file này như 1 chìa khóa -> trc khi server muốn gửi 1 file nào lên cloudinary -> trình ra file này để chứng minh - tôi là chủ tài khoản 
    - 1 hàm ở server : (vd uploadController)
        - tác dụng: nhận file từ fe -> đẩy lên cloudinary -> nhận url cloudinary gửi về và trả về cho fe
    - 1 hàm ở fe : (vd uploadImageService trong file productsService)
        - tác dụng:  lấy file từ máy ng dùng -> đóng gói lại -> gửi về fe -> nhận lại url của cloudinary mà be gửi lại
    hàm helper:
    - 1 hàm dùng để lọc ảnh ở be : vd (uploadMiddleware)


note : 
    + formData.append(KEY) ⇔ upload.single(KEY)
    
    - lý do phải lưu ảnh vào RAM để gửi lên cld vì:
        + Server là trung gian: Để bảo vệ API Key.
        + RAM là trạm trung chuyển tốc độ cao: Để Server nhận xong là "ném" đi ngay, không tốn thời gian ghi xuống ổ cứng.
        + Định dạng dữ liệu: Cần gom đủ dữ liệu vào RAM để chuyển đổi sang định dạng mà Cloudinary có thể đọc hiểu.
        3. Bản chất kỹ thuật: "Data Stream" (Luồng dữ liệu)
            - Bạn hình dung file ảnh 5MB không "bay cái vèo" 1 cục đến Server ngay lập tức. Nó được cắt nhỏ thành hàng nghìn gói tin li ti gửi qua mạng.
            Server cần phải:
                + Gom đủ các gói tin đó lại.
                + Ghép thành một khối dữ liệu hoàn chỉnh.
                + Khối dữ liệu hoàn chỉnh đó chính là cái Buffer (nằm trong RAM).
                + Chỉ khi có đủ cái Buffer này, Server mới có thể convert nó thành base64 (Data URI) để gửi cho Cloudinary theo đúng định dạng mà Cloudinary yêu cầu.


luồng đi dữ liệu:
    PHẦN 1: GIAI ĐOẠN UPLOAD (GHI DỮ LIỆU)

    Bước 1: Client (React/Next.js) đóng gói
        + Admin chọn một file ảnh (ví dụ: giay-nike.jpg) từ máy tính.
        + Code Frontend tạo một "phong bì" chuyên dụng tên là FormData.
        + Nó bỏ file ảnh vào phong bì và dán nhãn là "image" (phải trùng tên với Server).
        -> Gửi phong bì này đi bằng axios.post("/api/upload", formData).
    Bước 2: Server (Node.js) - Trạm gác cổng (Middleware)
        + Request đến Server, gặp ngay chốt chặn upload.single("image") (Multer).
        Multer kiểm tra:
            - File có đúng đuôi ảnh không? (FileFilter).
            - ile có nặng quá 5MB không? (Limits).
            - Nếu hợp lệ: Multer "hứng" toàn bộ dữ liệu file và giữ tạm trong RAM (không lưu xuống ổ cứng).
            - Dữ liệu lúc này nằm ở biến req.file.buffer.
    Bước 3: Server (Node.js) - Xử lý & Chuyển tiếp (Controller)
        - Hàm uploadImage (Controller) được gọi.
        - Nó lấy req.file.buffer (dạng nhị phân 010101...) chuyển đổi sang dạng chuỗi Base64 (Data URI) để Cloudinary hiểu được.
        - Server dùng "chìa khóa" (API_KEY, API_SECRET) để mở cửa kết nối với Cloudinary.
        - Server gửi chuỗi Data URI đó lên Cloudinary.
    Bước 4: Cloudinary (Kho chứa)
        - Nhận dữ liệu, giải mã và lưu thành file ảnh trên hệ thống ổ cứng của Google/AWS (nền tảng Cloudinary dùng).
        - tạo ra một đường dẫn công khai (Public URL): https://res.cloudinary.com/.../giay-nike.jpg.
        - Trả đường dẫn này về cho Server Node.js của bạn.
    Bước 5: Server trả kết quả & Client lưu Database
        - Server nhận URL từ Cloudinary $\rightarrow$ Trả JSON về cho Client: { url: "https://..." }.
        - client nhận được URL.
        Quan trọng: Client lấy URL này, ghép vào form thông tin sản phẩm (gồm tên, giá, mô tả...) và gọi tiếp API createProduct.
        Database chỉ lưu đúng cái chuỗi URL đó vào cột thumbnailUrl
